# Phase 11.1 — Production Network Identity Decision

## Purpose

Create the controlled decision record for IndoChain production network identity without inventing or prematurely assigning mainnet identifiers.

This phase records the decision boundary. It does not authorize mainnet launch.

## Current known identity

The existing testnet identity is documented as:

- Network: `testnet`
- Network ID: `ind-testnet-1`
- Chain ID: `777101`
- Genesis: canonical testnet genesis artifact

These values belong to testnet and must not be reused for mainnet.

The repository currently exposes a testnet seed example configuration; no production mainnet seed configuration is generated by this phase.

|---|---|---|
| Network name | TBD | Approve final production name |
| Network ID | TBD | Approve unique production network ID |

## Identity invariants

The approved mainnet must have a distinct and immutable identity boundary for:

- network ID;
- chain ID;
- genesis artifact/hash;
- protocol version;
- production P2P configuration;
- production persistent datadirs;
- node/P2P identities;
- bootstrap/seed configuration.

Changing a genesis-critical identity after genesis approval requires a new genesis artifact and a new approval cycle.

## Testnet isolation

Mainnet must not reuse:

- testnet genesis;
- testnet persistent chain state;
- testnet node/P2P identity;
- testnet bootstrap configuration;
- testnet-only operator configuration;
- testnet network or chain identifiers.

A production deployment must fail closed or refuse startup when its configured identity does not match the approved production identity.

## dIDR semantic continuity

The established ecosystem accounting relationship remains:

**1 dIDR = 1000 Rupiah**

This identity decision does not change native dIDR semantics and does not turn dIDR into a freely tradable asset by itself.

## Approval evidence

The final identity decision must record:

1. approved network name;
2. approved network ID;
3. approved chain ID;
4. approved protocol version;
5. approver/release authority;
6. decision timestamp;
7. rationale and collision/isolation check;
8. genesis-generation input reference.

Do not place private keys or credentials in the decision record.

## Gate

Until the above values are explicitly approved, production configuration and production genesis must remain **TBD**.

No placeholder value may be treated as a production identifier merely because it is syntactically valid.

## Acceptance criteria

- Testnet and mainnet identity boundaries are explicit.
- Production identifiers remain unresolved until formally approved.
- Genesis generation is downstream of the identity decision.
- P2P and RPC boundaries are part of the production identity/configuration review.
- dIDR semantics remain unchanged.
- No mainnet launch authorization is implied.
- No consensus implementation change is required by this documentation phase.
- CI status remains separate from the identity decision.
